# EngineRoom — Business Operations Platform

Multi-tenant operations platform built for Nigerian businesses. The current vertical is gym management — admins manage members, trainers, billing, and plans; members self-serve their profile, check-ins, BMI, and AI-generated workout plans.

**Live:** Deployed on Vercel · **Stack:** Next.js 15 · Supabase · Paystack · Claude AI · shadcn/ui

---

## Vision

EngineRoom is designed to grow beyond gyms. The underlying architecture — multi-tenancy, role-based access, payments, notifications, and AI — applies across verticals. Planned or considered expansions:

| Vertical | Description |
|----------|-------------|
| **Gym Management** | Current vertical — members, trainers, check-ins, workout plans, billing |
| **Inventory & Retail** | Stock tracking, low-stock alerts, supplier management for supermarkets and retail stores |
| **HR & People Ops** | Employee records, leave management, payroll tracking, onboarding workflows |
| **Corporate Communications** | Internal announcements, team notifications, document distribution, org-wide broadcasts |

Each vertical shares the same auth, tenant isolation, and billing infrastructure — only the domain-specific modules differ.

### Platform Admin (Super-Admin)

> **Access model:** Separate route group `/super-admin` within the same Next.js app, accessible only to accounts with the `platform_admin` role. Can be served on a custom subdomain (e.g. `admin.engineroom.ng`) via Vercel domain aliases with a host-based redirect in `next.config.ts`.

> **Gym onboarding policy:** New gyms registered via the public sign-up form do not go live immediately. They enter a **pending approval** state and must be reviewed and approved by a super-admin before they can access the platform. This prevents unauthorised or spam tenants.

## Pending Environment Variables

These need to be added to Vercel before the related features work in production:

| Variable | Where | Why |
|----------|-------|-----|
| `CRON_SECRET` | Vercel env vars | Secures `/api/cron/expiry-notifications`. Without it, automated expiry alerts return 401 and never fire. |
| `NEXT_PUBLIC_SITE_URL` | Vercel env vars | Set to `https://gaas-web-chi.vercel.app`. Used in invite/email redirect URLs. Without it, invite links fall back to localhost and fail in production. |
| `RESEND_API_KEY` | Vercel env vars | Required for member welcome emails to send. |
| `RESEND_FROM_EMAIL` | Vercel env vars | From address — must match a verified Resend domain. Use `EngineRoom <onboarding@resend.dev>` for testing (sends to verified addresses only). |

## Supabase Configuration (Required for Production)

In Supabase → Authentication → URL Configuration:

| Setting | Value |
|---------|-------|
| **Site URL** | `https://gaas-web-chi.vercel.app` |
| **Redirect URLs** | `https://gaas-web-chi.vercel.app/**` |

Without these, invite links and magic links will fail to redirect correctly.
